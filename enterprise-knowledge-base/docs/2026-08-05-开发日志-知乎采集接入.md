# 2026-08-05 开发日志 — 知乎企业号采集接入

## 一、目标与结论

微信公众号采集已稳定运行，本次按同一套多源采集框架接入**知乎企业号**（数据开放平台用户内容 API），全量文章 + 回答入库并进入 RAG 检索与引用溯源链路。

结果：抓取 65（文章 41 + 回答 24）→ 入库 62 → 跨平台去重合并 3 → 0 失败；端到端问答命中知乎内容且引用携带永久原文链接。

## 二、接口选型

- **主链路**：`GET https://developer.zhihu.com/api/v1/user/contents`（用户内容 API）。鉴权 `Bearer <Access Secret>` + `X-Request-Timestamp`；不传 `X-OAuth-Token` 拉调用方本账号数据。`ContentType=article/answer` 两轮拉取，`Offset/NextOffset` 分页（Limit≤50），`Paging.Totals` 用于对账。
- **搜索类 API（zhihu_search/global_search）不用于入库**：query 驱动、Count≤10/20，无法全量枚举本账号内容；留作将来智能体搜索增强的候选。
- **全文**：接口仅返回 Summary（实测约 200 字）。全文层按内容 Url 抓公开页（`js-initialData` JSON 优先，RichText div 配平扫描兜底，`app/collector/zhihu_page.py`）；**公开页裸访 403 防爬**，无 Cookie 时自动降级 Summary 入库（`extra.fulltext=false`），不中断同步。

## 三、配置与凭证位置（重要）

- 凭证与开关填在 **`backend/.env`**：`ZHIHU_ACCESS_SECRET`、`ZHIHU_COOKIE`（可选）、`ZHIHU_FETCH_FULLTEXT`（当前 false）、`ZHIHU_PAGE_DELAY=1.5`。
- **根 `.env` 不再放任何 ZHIHU 运行时配置**：compose 会把根 `.env` 注入为容器环境变量，空值会遮蔽 `backend/.env` 的 dotenv 值（本次踩坑：Secret 填了却不生效，排查发现是根 `.env` 空占位遮蔽）。根 `.env` 仅保留 `ZHIHU_SOURCE_NAME=特莱顿知乎号` 展示名。
- 容器重建后需重跑 `docker exec kb-backend pip install aiosqlite alembic`（镜像未含，预存问题）。

## 四、适配器设计（`app/collector/adapters/zhihu.py` 重写）

- 游标：`None → article:{offset} → answer:{offset} → None`（仿微信多源游标；拉完重置，去重兜底）。
- **自限流**：平台有秒级限频（错误码 30001 "second limit exceeded"，探测时连续两请求即触发）。适配器 `_throttle()` 保证相邻 API 请求间隔 ≥ `page_delay`；pipeline 另保留通用页间延时（`BaseCollector.page_delay`）。
- 错误码映射：`ZhihuApiError`（Code!=0）；30001 由 pipeline 退避重试吸收，20001/30002 记日志失败。
- `external_id`：Url 解析 `article:{id}`/`answer:{id}`（兜底全 Url）；`original_url` 去 utm 参数；回答正文前拼「问题：{标题}」保留上下文。
- `health_check` 真实探测（Limit=1）。
