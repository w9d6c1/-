# RAG 检索增强拓展路线图

> 状态:**拓展储备,尚未实施**
> 背景:当前系统为**封闭域 RAG**(仅检索用户上传的文档/FAQ),这是刻意设计,以保证私有化、防幻觉、防泄密、可审计。
> 本文记录"让检索不再单一"的可选增强方向,按风险从低到高排列,供后续迭代参考。
> 关联:`操作指南.md`(第 3/5 节)、`OPTIMIZATION.md`、`../LANGGRAPH_NODES.md`

---

## 现状分析(基于代码核对)

| 事实 | 位置 | 影响 |
|------|------|------|
| 检索仅召回上传内容,按 scope 过滤 | `agents/nodes/retrieve.py` | 封闭域,库外问题拒答 |
| Prompt 硬约束"只基于文档,无则拒答" | `agents/nodes/generate.py` | "单一"的直接原因 |
| ReAct 工具框架已跑通,但两工具都只查内部库 | `agents/nodes/tools.py` | C 只需加工具,无需改架构 |
| `FusionResult` 含 `metadata` / `scope` 字段 | `retrieval/fusion.py` | 外部来源可复用此结构,不破坏隔离 |
| 低置信未自动落库 | `agents/nodes/output.py` 仅算 confidence | B 闭环缺采集环节 |
| 路由按查询长度判定(≤15字→FAQ) | `agents/nodes/route.py` | 粗糙,本次改造不涉及 |

---

## 方向 B — 知识闭环运营(风险低,建议优先)

**目标**:低置信/未命中问题自动进 `unanswered_question` 表,运营在 `UnansweredList.vue` 转 FAQ。

| 步骤 | 文件 | 改动 |
|------|------|------|
| B1 | `agents/state.py` | 加字段 `is_answered: bool` |
| B2 | `agents/nodes/logging.py` | `confidence < 阈值` 或 `retrieved_docs 为空` 时,写入 `unanswered_question`(按 question 去重) |
| B3 | `models/` | 确认/补 `unanswered_question` 表 model + 迁移 |
| B4 | `api/admin/` | 确认未命中列表 / 转 FAQ 端点存在(前端 `UnansweredList.vue` 已具备) |

**验证**:问一个库里没有的问题 → 后台"未命中问题"出现该条 → 转 FAQ 成功。

---

## 方向 C — 接入工具/API(解决动态数据,推荐主攻)

**目标**:智能体查订单/工单/时间等实时结构化数据。

| 步骤 | 文件 | 改动 |
|------|------|------|
| C1 | `agents/tools.py` | 新增 `@tool`,如 `query_order(order_id)` / `get_current_time()`;返回文本或包成 `FusionResult`(`metadata.source_type="tool"`) |
| C2 | `agents/tools.py` `_execute_tool` | 加分支路由到新工具 |
| C3 | `agents/tools.py` `TOOL_SYSTEM_PROMPT` | 补充工具说明与调用时机 |
| C4 | 新建 `services/external_api.py` | 封装外部系统调用(超时/重试/降级),密钥走 `.env` |
| C5 | 权限 | 敏感工具(订单查询)校验 `user_scopes`,防越权 |

**要点**:工具失败必须优雅降级(现有 try/except 返回空),不阻断主流程。仅内部智能体启用(客服图无 tools 节点,如需另议)。

**验证**:问"订单 12345 状态" → 触发 `query_order` → 返回实时数据 + 来源标注。

---

## 方向 D — 联网/外部语料(风险高,需合规权衡)

⚠️ **合规提醒**:与"私有化、防泄密、可审计"初衷冲突。建议**默认关闭、开关控制、仅对 public/customer scope 开放、internal 场景禁用**。

| 步骤 | 文件 | 改动 |
|------|------|------|
| D1 | `.env` + `core/config.py` | 加 `ENABLE_WEB_SEARCH=false` 开关 + 搜索 API Key |
| D2 | 新建 `retrieval/web_search.py` | 封装搜索引擎/外部 KB,结果转 `FusionResult`(`scope="web"`, `metadata.source_type="web"`, `metadata.url`) |
| D3 | `agents/tools.py` | 新增 `web_search` 工具(开关 + scope 双重门控) |
| D4 | `agents/nodes/generate.py` | 外部来源答案**必须标注 URL + "外部来源,仅供参考"**,置信度封顶 |
| D5 | `agents/nodes/output.py` `compute_confidence` | 外部来源结果降权 |
| D6 | `agents/nodes/logging.py` | 记录外部来源使用,供审计 |

**验证**:开关开 → 问库外常识 → 返回带 URL 的外部答案 + 免责标注;开关关 → 回退"未找到"。

---

## 横切 — 混合作答(建议随 B/D 一起做)

`generate.py` prompt 从"无则拒答"改为分级:
- 知识库命中 → 严格 grounding(现状)
- 仅外部/工具来源 → 标注来源 + 降置信
- 全空 → 拒答 + 触发 B 的未命中采集

---

## 建议执行顺序与工作量

| 优先级 | 阶段 | 工作量 | 风险 |
|--------|------|--------|------|
| 1 | B 知识闭环 | 小(半天) | 低 |
| 2 | C 工具/API | 中(1-2天,取决于外部系统) | 中 |
| 3 | D 联网 + 混合作答 | 中(1-2天) | 高(合规) |

**测试**:每阶段后跑 `pytest tests/unit tests/integration tests/security --no-cov`;D 阶段务必验证 `tests/security/` 的跨库隔离不被外部来源破坏。
