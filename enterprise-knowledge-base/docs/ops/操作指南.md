## 1. 系统概览

一套私有化部署的企业智能问答系统,核心由**两个 AI 智能体** + **知识库管理后台**组成。

| 智能体 | 入口 | 知识范围 | 特性 | 限流 |
|--------|------|---------|------|------|
| **内部智能体** | `/api/agent/internal/chat` | public + internal | 工具调用、查询分解 | 30/min |
| **客服智能体** | `/api/agent/customer/chat` | public + customer | 转人工、无工具调用 | 60/min |

**技术栈**

- 后端:FastAPI + LangChain + LangGraph
- 前端:Vue3 + Element Plus + Vite
- 大模型:DeepSeek(外部 API)
- 嵌入:BGE-Large-ZH(1024维)/ 重排:BGE-Reranker-v2-m3
- 检索:Milvus 2.4(向量) + Elasticsearch 8.15(BM25) + RRF 融合
- 存储:MySQL 8(业务) + PostgreSQL 16(对话状态) + Redis 7(缓存) + MinIO(文档)
- 可观测:Prometheus + Grafana + Loki

**三重安全隔离**:向量层三 Collection 物理隔离 → 路由层 `_strip_internal_scopes` 强制剥离 → 接口层 JWT + API Key 鉴权。

## 2. 部署运维细节

### 2.1 环境要求

| 组件 | 最低版本 | 说明 |
|------|---------|------|
| Docker | 24+ | 需 Compose v2 |
| Docker Compose | 2.20+ | 使用 `docker compose`(非连字符) |
| RAM | ≥16GB | Milvus 4G + ES 2G + MySQL + 后端 |
| 磁盘 | ≥50GB 可用 | 向量/ES 索引 + 日志 |
| OS | Linux / Windows(WSL2) / macOS | — |

### 2.2 首次部署(五步)

```bash
# 1. 获取代码
git clone <repo-url> /opt/knowledge-base
cd /opt/knowledge-base/enterprise-knowledge-base

# 2. 配置环境变量
cp .env.prod .env
```

编辑 `.env`,**必须修改**以下密钥:

| 变量 | 生成方式 |
|------|---------|
| `MYSQL_ROOT_PASSWORD` / `MYSQL_PASSWORD` | `openssl rand -hex 16` |
| `POSTGRES_PASSWORD` | `openssl rand -hex 16` |
| `MINIO_ACCESS_KEY` | `openssl rand -hex 8` |
| `MINIO_SECRET_KEY` | `openssl rand -hex 16` |
| `JWT_SECRET_KEY` | `openssl rand -hex 32`(≥64字符) |
| `LLM_API_KEY` | 必填:DeepSeek API Key |
| `CORS_ORIGINS` | 生产域名,逗号分隔 |
| `DEBUG` / `LOG_LEVEL` | 生产设 `false` / `INFO` |
| `GRAFANA_PASSWORD` | 修改为非 admin/admin |

```bash
# 3. 生成 SSL 证书(内网自签名)
cd docker/ssl
openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout server.key -out server.crt -subj "/CN=your-server-ip"
# 公网域名改用 Let's Encrypt(certbot certonly --standalone -d your-domain.com)

# 4. 一键启动全部服务(14 个容器)
cd /opt/knowledge-base/enterprise-knowledge-base
docker compose -f docker-compose.prod.yml up -d

# 5. 等待健康检查(首次 Milvus/ES 约 2-3 分钟)
docker compose -f docker-compose.prod.yml ps   # 期望 13/13 healthy
```

## 3. 智能体对话流程

### 3.1 核心数据流

```
用户提问
  → Nginx (HTTPS + WAF)
  → FastAPI (/api/agent/*/chat)
  → LangGraph Workflow(见下)
  → SSE 流式输出
  → ChatLog 异步落库 (MySQL) + Checkpoint 状态保存 (PostgreSQL)
```

### 3.2 内部智能体(11 节点,条件分支 + ReAct 循环)

图文件:`backend/app/agents/graph.py`

```
START
 → [1] validate_input   输入校验(SQL注入/Prompt注入/禁答词/空查询)
 → [2] auth             JWT 鉴权 + scope 映射
 → [3] rewrite          查询改写(多轮合并/指代消解/同义词, 调 LLM)
 → [4] route            路由决策
      ├─ faq ─→ [5a] faq_match(余弦≥0.92短路) → [9] output → [10] log → END
      └─ retrieve ─→ [5] retrieve → [6] tools → [7] context → [8] generate
                        → [9] output → [10] log → END
                     (若 has_tool_calls ∧ iteration<3 → 回到 [5] 循环)
```

| 节点 | 文件 | 功能 |
|------|------|------|
| validate_input | `nodes/validate.py` | 检测注入/禁答词,输出 `is_blocked` |
| auth | `nodes/auth.py` | 解析 JWT,加载角色,映射 scope |
| rewrite | `nodes/rewrite.py` | 历史合并 + 指代消解 + 同义词(LLM) |
| route | `nodes/route.py` | 短查询→FAQ,长查询→RAG,空→reject |
| retrieve | `nodes/retrieve.py` | BM25 ∥ 向量 → RRF(k=60) → Reranker(Top-K) |
| tools | `nodes/tools.py` | ReAct 循环:`search_knowledge_base` / `decompose_and_search`,上限 3 次 |
| context | `nodes/context.py` | 组装上下文,Token 上限 3000,按优先级截断 |
| generate | `nodes/generate.py` | LLM 生成答案 + 引用来源(退避 1s/2s/4s) |
| output | `nodes/output.py` | 敏感词脱敏 + 置信度标记 + 合规校验 |
| log | `nodes/logging.py` | 全链路写 chat_log(含 node_latency_ms) |

### 3.3 客服智能体(6 节点,无工具 + 转人工)

图文件:`backend/app/agents/customer_graph.py`

关键差异:
- `customer_route_node`:路由前先调 `_strip_internal_scopes()` 剥离 internal
- `customer_faq_match_node`:硬编码仅匹配 `["public", "customer"]`
- `human_handoff_node`:**4 类转人工触发** — 低相似度检索 / 转人工关键词 / 连续 2 轮不满 / 模型输出转接标记;触发后推送对话摘要到人工队列

### 3.4 状态与会话恢复

- State:`backend/app/agents/state.py` — `AgentState` TypedDict(30+ 字段)
- Checkpointer:`PostgresSaver`(PostgreSQL),通过 `thread_id` 恢复完整历史

### 3.5 智能体 API 端点

| 端点 | 方法 | 说明 |
|------|------|------|
| `/api/agent/internal/chat` | POST | 内部,限流 30/min |
| `/api/agent/internal/chat/stream` | POST | 内部,SSE 流式 |
| `/api/agent/customer/chat` | POST | 客服,限流 60/min |
| `/api/agent/customer/chat/stream` | POST | 客服,SSE 流式 |
| `/api/agent/rewrite` | POST | 查询改写测试 |
| `/api/agent/status` `/api/agent/info` | GET | 健康 / 模块状态 |

## 4. 日常使用

### 4.1 普通用户 — 智能问答

浏览器访问 `https://<服务器地址>` → 登录 → "智能问答"

1. 顶部切换 **"内部问答"** 或 **"客服咨询"**
2. 输入问题,回车发送
3. 查看回答及**置信度**:🟢 ≥80% 可直接用 / 🟠 50-80% 建议复核 / 🔴 <50% 查原文档
4. 反馈:👍 有用 / 👎 需改进(可填建议)

### 4.2 管理后台功能

> ⚠️ 管理后台限内网访问,外网需 VPN。

| 模块 | 前端视图 | 操作 |
|------|---------|------|
| 仪表盘 | `Dashboard.vue` | 今日问答量、FAQ 命中率、满意度、待审数 |
| 分类管理 | `CategoryList.vue` | 知识分类 CRUD |
| FAQ 管理 | `FaqList.vue` | 问答对录入,保存即生效;支持批量导入 |
| 文档管理 | `DocumentList.vue` | 新建→上传内容→分块确认→提交审核→上线 |
| 审核中心 | `ReviewCenter.vue` | 通过上线 / 驳回退回草稿 |
| 用户反馈 | `FeedbackList.vue` | 查看点赞/踩,分析分布 |
| 未命中问题 | `UnansweredList.vue` | 转 FAQ(AI 生成草稿)/忽略/待处理 |
| 词库管理 | `DictionaryList.vue` | 同义词映射、敏感词(拦截/过滤) |
| 角色权限 | `PermissionList.vue` | 配置角色可访问 scope |
| 审计日志 | `AuditLog.vue` | 操作/对话/安全三表 |

### 4.3 角色权限

| 角色 | 权限范围 | 适用人员 |
|------|---------|---------|
| superadmin | 全部权限 + 所有 scope | IT 管理员 |
| dept_admin | 本部门文档 + public/internal | 部门主管 |
| operator | FAQ/文档编辑 | 内容运营 |
| readonly | 仅查阅 public | 普通员工 |

### 4.4 数据驱动优化(每周迭代)

收集(未命中 Top20 / 差评 FAQ / 节点延迟 / 安全事件)→ 分析 → 优化(补知识、改答案、调参数、优化 Prompt)。SQL 查询与参数调优表见 `OPTIMIZATION.md`。

关键可调参数:

| 参数 | 默认 | 文件 |
|------|------|------|
| FAQ 余弦阈值 | 0.92 | `agents/nodes/faq.py` |
| RRF k 值 | 60 | `retrieval/fusion.py` |
| Reranker Top-K | 5 | `agents/nodes/retrieve.py` |
| 分块大小 / 重叠 | 800 / 200 | `services/chunking.py` |

### 5.3 常见扩展场景

**新增管理后台接口**
1. 在 `backend/app/api/admin/` 新建模块,定义 `router = APIRouter(prefix="/xxx", tags=[...])`
2. 在 `admin/__init__.py` 中 `router.include_router(xxx_router)`
3. 业务逻辑放 `services/`,数据模型放 `models/`,请求/响应模型放 `schemas/`
4. 前端在 `src/api/` 加接口封装,`src/views/admin/` 加视图,`src/router/` 注册路由

**新增智能体节点**
1. 在 `agents/nodes/` 新建节点函数,读写 `AgentState`(`state.py`)字段
2. 在 `graph.py` / `customer_graph.py` 用 `add_node` / `add_edge` / `add_conditional_edges` 接入
3. 若 LLM 调用参考 `generate.py`(重试 + 指数退避)

**新增 ReAct 工具**(仅内部智能体)
- 在 `agents/nodes/tools.py` 注册工具函数,返回结构会追加到 `retrieved_docs`;注意循环上限 3 次

**调整检索/生成**:改 `retrieval/fusion.py`(RRF)、`nodes/retrieve.py`(Reranker Top-K)、`nodes/generate.py`(Prompt 模板)。

### 5.4 测试

```bash
cd backend
python -m pytest tests/unit/ tests/integration/ tests/security/ -q --no-cov  # 全量
```

要求:单元/安全测试 100% 通过,覆盖率 ≥80%。新增功能须先写测试(TDD)。

### 5.5 安全红线

- 参数化查询(禁字符串拼接 SQL);输入经 `validate.py` 校验
- 客服路径务必保留 `_strip_internal_scopes`,禁止泄露 internal 知识
- 密钥走环境变量,禁止硬编码;不 log 敏感数据
- 改动智能体/检索后,运行 `tests/security/` 验证隔离与敏感词拦截

### 5.6 已知限制

- 前端文件上传仅支持文本粘贴(MinIO 集成待完成)
- 外部工具(订单/工单)、渠道对接(微信/企微/飞书)待实现
- ES/Milvus 依赖 Docker network,跨机部署需调整
- 仅支持中文

## 6. 常见问题

| 问题 | 处理 |
|------|------|
| 搜索结果不准 | 查"未命中问题",补 FAQ/文档;或降低 FAQ 余弦阈值 |
| 文档更新未生效 | 审核通过后自动同步向量,约 1-3 分钟 |
| 敏感词误拦正常问题 | 词库管理 → 删除对应敏感词 |
| 批量导入已有知识 | `import_seed_data.py` 从 CSV 导入 |
| 容器不健康 / 服务故障 | 见 `TROUBLESHOOTING.md` |
| 备份与恢复 | 见 `BACKUP.md` |
| 监控指标含义 | 见 `MONITORING.md` |
