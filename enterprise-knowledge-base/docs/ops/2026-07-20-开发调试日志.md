# 2026-07-20 开发调试日志

## 概述

全天围绕智能问答系统进行性能调优、输出格式优化、链路排查。修改涉及 14 个文件。

## 一、系统启动与性能优化

### 1.1 监控栈停止（释放内存）

Docker Desktop 分配 7.3GB，运行 16 个容器时内存占用达 85%（~4.1GB），导致系统响应缓慢。

**操作：**
- 停止 prometheus、grafana、loki、promtail 四个监控容器（开发环境不需要）
- 停止另一项目（Dify）的 5 个容器（nginx、ssrf_proxy、db_postgres、redis、weaviate）
- 释放约 1.2GB 内存，负载降至 40%

### 1.2 Nginx 启动失败修复

停掉 grafana 后，nginx 配置中引用 `upstream grafana` 的 host 无法解析，导致 nginx 无法启动。

**操作：** 注释 `docker/nginx/conf.d/default.conf` 中的 Grafana location 块

## 二、验证码接口修复

### 2.1 Backend Uvicorn 卡死

uvicorn 事件循环被 `coll.load()` 同步阻塞调用卡住，所有请求超时。

**操作：** 重启后端容器

### 2.2 WAF ModSecurity 拦截 JSON

ModSecurity 的 OWASP CRS 规则对 POST JSON body 解析失败（Windows curl 换行符问题），返回 400。

**操作：** `docker/waf/waf-proxy.conf` 中 `/api/admin/auth/` 和 `/api/agent/` 加 `modsecurity off;`

### 2.3 WAF 重启后 Nginx DNS 缓存旧 IP

WAF 重启获得新 IP，nginx 的 `upstream backend` 缓存了旧 IP，导致 502。

**操作：** 重启 nginx 刷新 DNS

## 三、智能问答链路排查与修复

### 3.1 Milvus Collection 加载阻塞

核心问题：`coll.load()` 是 PyMilvus 同步阻塞调用，对空 collection（coll_customer）加载会永久挂起，阻塞 asyncio 事件循环。

**修复：** `retrieval/milvus_client.py`
- 模块级别 `_ensure_connected()` 避免重复 `connections.connect`
- `coll.load(timeout=10)` 加超时
- `dense_search` 加异常捕获（collection 未加载时搜索会抛异常）
- `_get_or_create_collection_async` 使用 `loop.run_in_executor` 线程池执行同步操作

### 3.2 检索超时保护

LangGraph 图执行中的 `hybrid_retrieve` 调用无超时，某个 scope 的 Milvus 加载失败会导致整个请求永久等待。

**修复：3 个文件加 `asyncio.wait_for + timeout=15s`**
- `agents/customer/retrieve.py` — 客服检索节点 scope 循环
- `agents/nodes/retrieve.py` — 内部检索节点 scope 循环
- `agents/nodes/tools.py` — 工具调用检索

### 3.3 客服智能体路由修复

`customer_route_node` 按字符数判断路由（≤15chars 走 FAQ，>15 走检索），导致长问题跳过 FAQ 匹配。

**修复：** `agents/customer_graph.py` 取消字符限制，所有查询统一走 FAQ 优先

## 四、输出格式优化

### 4.1 生成 Prompt 重写

**文件：** `agents/customer/generate.py`、`agents/nodes/generate.py`

新增规则：

### 4.2 FAQ 上下文标签清洗

**文件：** `agents/customer/faq.py`、`agents/nodes/faq.py`

`context` 字段从 `[FAQ 精准匹配] {答案}` 改为 `参考FAQ答案：\n{答案}`

### 4.3 输出节点后处理兜底

**文件：** `agents/nodes/output.py`

`validate_output_node` 中增加正则清理（3层防线）：
```
1. 机器标签：[来源:xxx]、[FAQ 精准匹配]
2. Markdown：# ## ### 标题、--- 分隔线、缩进/非缩进 -  * 列表
3. 思考文本：首先/我先/用户等开头的搜索描述句
```

### 4.4 工具节点思考泄露修复

**文件：** `agents/nodes/tools.py`

- `tool_decision_node` 中 AI 消息的 `content` 置空（函数调用不需要文本）
- `_format_docs_for_llm` 去除 `[文档1] 来源:xxx` 标签
- `search_knowledge_base` 工具返回去除 `[来源:xxx]` 标签

### 4.5 流式端点清洗

**文件：** `app/api/agent/__init__.py`

- **内部流式 `_stream_events`：** 原来完全不发 `done` 事件，前端只看到 raw token 累计。新增 `done` 事件发送清洗后答案
- **客服流式 `_customer_stream_events`：** `on_chain_end` 过滤空 `final_answer`（之前对每个节点都发 done）
- 两个端点都在 `done` 答案上执行 7 条正则清洗

## 八、遗留问题

1. **Milvus coll_internal 加载不稳定：** 386 实体的 collection 在某些情况下 `load()` 超时（10s），导致内部智能体的密集检索降级为仅 BM25。需排查 Milvus 服务端性能。
2. **DeepSeek 数字幻觉：** 列表中偶尔输出 `大幅.` 替代 `1.`，模型层面的问题。
3. **流式 token 期间仍显示原始内容：** done 事件可覆盖最终答案，但 token 流式期间用户会短暂看到未清洗内容。
