> 状态:**规划存档**;企业微信渠道 **实现中/已实现**(见文末实现记录)
> 目标:内部问答接 **企业微信 + 钉钉**;客服问答接 **微信小程序 + 官网**

## 目标架构

```
                       ┌─────────────────────────────────┐
  内部员工              │         渠道适配层 (新增)          │
  ├─ 企业微信 ─────────▶│  channels/wecom/                │──┐
  └─ 钉钉 ─────────────▶│  channels/dingtalk/             │  │  内部智能体
                       │                                 │  └─▶ /api/agent/internal/chat
  外部客户              │                                 │
  ├─ 微信小程序 ───────▶│  channels/miniprogram/          │──┐
  └─ 官网 Web ─────────▶│  channels/web/ (已有前端)        │  │  客服智能体
                       └─────────────────────────────────┘  └─▶ /api/agent/customer/chat
```

**设计原则**:渠道均为薄适配器,统一收敛到已有两个智能体端点;智能体核心不改,仅在外围加渠道层 + 身份映射层。

---

## 通用基础层(所有渠道共用)

| 模块 | 路径(拟) | 职责 |
|------|---------|------|
| 渠道路由 | `api/router.py` 挂载 `channels/*` | 各渠道回调入口 |
| 身份映射 | `services/identity_service.py` | 渠道 userid/openid → 系统 user/role/scope |
| 会话映射 | 复用 Redis (`agents/cache.py`) | 渠道用户 → thread_id 持久映射(多轮上下文) |
| 异步回复 | 复用 `core/notifier.py` 思路 | AI 生成 >5s,先占位后异步推送 |
| 配置扩展 | `core/config.py` | 各渠道凭证 |

**内部身份映射策略**(本期采用):企微/钉钉 userid → 统一映射为 `internal` 等效角色(scope=public+internal)。后续如需部门细分,再建 `userid ↔ sys_user` 映射表。

## 渠道 1:企业微信(内部)— 本期实现

自建应用模式。流程:**验签 → 解密 → 身份映射 → 调内部智能体 → 异步回推**。

| 步骤 | 内容 |
|------|------|
| W1 | 企微后台建自建应用,获取 CorpId / AgentId / Secret / Token / EncodingAESKey |
| W2 | 回调 URL 验证(`GET`,校验 msg_signature + 返回解密 echostr) |
| W3 | 消息接收(`POST`,AES-CBC 解密 + XML 解析) |
| W4 | userid → 系统身份(身份层,内部=internal scope) |
| W5 | 调 `/api/agent/internal/chat` 拿回答 |
| W6 | 通过「应用消息发送」API 主动回推(access_token 缓存 Redis) |
| W7 | 超 5s 先回"正在思考…",异步推送最终答案 |

**实现文件**:
- `channels/wecom/crypto.py` — WXBizMsgCrypt(签名/AES 加解密)
- `channels/wecom/client.py` — access_token 缓存 + 主动发消息
- `channels/wecom/service.py` — 消息处理主流程
- `channels/wecom/router.py` — GET 验证 + POST 接收
- `services/identity_service.py` — 身份映射

## 关键技术约束

- **企微 5 秒超时**:被动响应必须 5s 内返回,AI 生成慢 → 先回占位 XML,再用主动消息 API 异步推送最终答案
- **access_token**:2 小时有效,缓存 Redis,避免频繁刷新(每日上限)
- **消息去重**:企微会重试,按 MsgId 幂等去重(Redis)
- **安全隔离**:内部渠道 = internal scope;严禁把 internal 权限泄露给客服渠道
