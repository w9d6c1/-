### PowerShell 陷阱（血泪教训）
- **不要用 PowerShell 的 Get-Content/-replace/Set-Content 编辑含中文的 .env 或代码文件**——会把 UTF-8 中文注释搞成乱码并吞换行（本会话已发生过一次 .env 事故，用 Write 工具重建修复）。
- 多行 `docker exec kb-backend python -c "..."` 用双引号包裹、内部单引号可行；嵌套双引号转义易碎，复杂脚本建议 Write 到临时文件再 `docker cp` 进容器执行。

## 已完成内容

### 1. 文档清洗（TDD）
- 新文件 `backend/app/services/text_cleaner.py`：管道 = 去 BOM/零宽字符 → 页标记（`=== Page N ===`/`[PN]`/`Page N of M`/整行`第N页`，含内联）→ 占位行（独立"表格/图片" + 符号-only 标题如 `### >`）→ 碎片合并（1-2 字 CJK 孤儿并入上行；独立列表符 `-`/`•`/`·`/`–` 与下行合并）→ CJK 空格规范化（保留运算符空格）→ 空行压缩。幂等、内容字符零丢失。
- 新文件 `backend/app/services/text_cleaner_llm.py`：`split_into_segments`（按 `#` 标题切、2000 字上限按行再切）、`llm_enhance_clean(text, use_llm)`（未配置 key/异常/输出长度偏差 >40% → 回退规则结果；结果与规则相同不标记 llm_enhanced）。
- 模型：`knowledge_doc` 增 `clean_status`(pending/cleaned/skipped/failed)、`clean_report`(JSON)、`raw_text`(清洗前原文)；迁移 `backend/alembic/versions/b003_add_doc_clean_fields.py`（**已对生产 MySQL 应用**；alembic 有双 head，主链 b002→b003，升级需指定 revision）。
- API（`app/api/admin/document.py`）：upload 增 `auto_clean: bool = Form(True)`（先清洗 raw 再 parse_text 入库，raw_text 存原文）；`POST /documents/{id}/clean`（body `{"use_llm": bool}`，默认 false，用 `Body(default_factory=CleanOptions)` 避 B008）；`POST /documents/bulk-clean`。
- 服务层 `document_service.py`：`update_content(..., auto_clean=True)`；`clean(doc_id, user, use_llm=False)`——**pdf/docx 不走 parse_text 保留行结构**（md/txt 才走），游标/状态语义与上传一致。
- 前端 `DocumentList.vue`：高级选项"上传后自动清洗"开关；列表"清洗"状态列；"清洗"按钮 + 对话框（LLM 开关 + 清洗报告展示）；批量清洗按钮。`api/document.ts` 增 cleanDocument/bulkCleanDocuments/CleanReport 类型。
