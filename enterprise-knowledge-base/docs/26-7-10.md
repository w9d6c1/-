## ✅ 任务 4：AI 模型迁移（本地 → SiliconFlow API）

### 背景

DeepSeek API 只提供 Chat 模型，没有 Embedding。本地加载 bge-large-zh (1.3G) + bge-reranker (2.2G) 共 3.5G，4G 服务器无法部署。

### 解决方案

SiliconFlow（硅基流动）免费提供完全相同的模型 API：

| 模型 | 本地大小 | SiliconFlow 费用 | 向量维度 |
|:---|:---:|:---:|:---:|
| `bge-large-zh-v1.5` (Embedding) | 1.3G | ¥0 | 1024（不变） |
| `bge-reranker-v2-m3` (Reranker) | 2.2G | ¥0 | N/A |

### 修改文件

| 文件 | 改动 |
|------|------|
| `app/core/config.py` | +`siliconflow_api_key`、`siliconflow_base_url` |
| `app/agents/embedding.py` | 重写：`HuggingFaceEmbeddings` → `httpx` POST SiliconFlow |
| `app/retrieval/reranker.py` | 重写：`FlagReranker` → `httpx` POST SiliconFlow |
| `.env` / `backend/.env` | +`SILICONFLOW_API_KEY` |
| `backend/docker/Dockerfile` | workers 4→2，移除 `COPY ../models` |

### 效果

| 指标 | 改前 | 改后 |
|:---|:---|:---|
| 后端内存 | 4G | ~500M |
| Docker 镜像 | ~5G | ~1.5G |
| 启动时间 | 60s+（下载模型） | 即时 |
| 模型费用 | 0 | ¥0 |

### 内存分配

```
backend 1G + elasticsearch 1G + milvus 512M + mysql 256M + waf 128M
```

- 密码：4 组 openssl rand -hex 随机生成
- .env.prod：gitignore 保护，不提交到仓库

### 部署时遇到的问题

| # | 问题 | 解决 |
|---|------|------|
| 1 | apt 不兼容（OpenCloudOS 是 dnf） | 改为手动 dnf 安装 certbot |
| 2 | 系统自带 nginx 占 80 端口 | `systemctl stop nginx` |
| 3 | DNS 未解析 | 腾讯云 DNS 控制台加 A 记录 |
| 4 | `docker-compose.prod.yml` 未提交到 Git | scp 单独上传 |
| 5 | Docker 镜像源 429 限流 | 换腾讯云镜像源 |
| 6 | `.env` / `.env.prod` 路径不匹配 | 手动 cp |
| 7 | master 分支切换 | `git checkout master` |
| 8 | 浏览器 502：网关上游 `frontend:5173` 与 prod 前端端口不符（prod 前端 Nginx 监听 80） | 让 prod 前端改听 5173，对齐 `default.conf` 上游：`nginx-frontend.conf` `listen 80→5173`、`Dockerfile` `EXPOSE 80→5173`、`docker-compose.prod.yml` 前端 `expose`/healthcheck `80→5173`，重建前端镜像 + 重启 nginx |
| 9 | 网关 80/443 完全连不上（nginx 从未启动）：前端 **prod 镜像一直构建失败** → nginx `depends_on frontend` 起不来 | 前端 `docker/Dockerfile` 两处缺陷：① `base` 只 `COPY package.json`，prod 阶段 `npm ci` 因缺 `package-lock.json` 失败；② prod 阶段漏 `COPY . .`，`npm run build` 无源码可构建。修复：`base` 改 `COPY package.json package-lock.json ./`；prod 阶段 `npm ci` 后补 `COPY . .` 再 `npm run build` |
| 10 | 镜像构建/拉取慢，关终端导致构建中断、栈未起来 | 用 `nohup docker compose ... up -d --build > ~/deploy.log 2>&1 &` 后台构建，`tail -f ~/deploy.log` 看进度；断线不影响后台进程 |
| 11 | 服务器 git clone 成嵌套目录 `~/enterprise-knowledge-base/enterprise-knowledge-base/`，在外层跑 compose 报 `path "./backend" not found`（外层是当初 scp 的游离文件） | 在嵌套真实项目目录内操作；证书 `docker/ssl/` 从外层 `cp` 进嵌套层 |
| 12 | backend 构建 `no space left on device`（40G 盘塞满）：`requirements.txt` 仍保留 `sentence-transformers`/`FlagEmbedding`/`langchain-huggingface`，拖入 torch+CUDA(数 GB)，但迁移后代码已用 httpx 调 SiliconFlow、根本不 import 它们 | 删除这 3 个依赖；服务器先 `docker builder prune -af` + `docker image prune -f` 清理，再 `git pull` 重建。镜像 3.3G→~1.5G |
| 13 | MySQL 3306 与主机 mysqld 冲突（exit 137 OOM） | prod.yml 移除 MySQL 3306 端口；内存 256M→512M |
| 14 | 前端 `target: prod` 跳过 nginx 阶段 → dist 未打包 | Dockerfile 最终阶段命名 `production`，compose `target: prod`→`production` |
| 15 | `ip-whitelist.conf` 被 `nginx.conf` 通配符 `*.conf` 在 http 级别全局 `deny all` → 403 | 改名为 `ip-whitelist.inc`，只在 `location /api/admin/` 显式 include |
| 16 | Docker 网络状态卡死，端口反复 `address already in use` | `systemctl restart docker`；减少无用 `127.0.0.1` 端口映射 |
| 17 | `deb.debian.org` apt 源构建 25 分钟 | 改为 `mirrors.aliyun.com` |
