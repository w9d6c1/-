## ✅ 任务 2：修复全量单测回归

### 问题诊断

全量单测中出现 ~25 个失败，集中在 `test_rewrite.py`、`test_faq_node.py`、`test_faq_loading.py`、`test_faq_vector_reload.py`、`test_customer_nodes.py`、`test_auth_rewrite_route.py`、`test_customer_api.py`、`test_dept_isolation.py`。根因分为三类：

### Category 3 — REAL SOURCE BUG：stdlib logger + structlog kwargs

**严重程度：生产级 bug**

`app/core/logging.py` 配置了 **structlog**（接受结构化 kwargs），但 ~16 个模块使用 stdlib `logging.getLogger(__name__)`，然后传入 structlog 风格的 kwargs：

```python
logger = logging.getLogger(__name__)  # stdlib
logger.info("faq_vectors_loaded", count=5)  # TypeError!
```

**影响**：
- **Hot-path**：`faq.py:41` 在 `_set_faq_vectors()` 内每次触发 → **FAQ 向量加载在启动和生产中静默失败**（被 lifespan 的 `startup_cache_skip` 吞掉）
- `audit_service.py` 8 处 → 后台审计日志在故障路径上崩溃
- 其余 ~14 个模块潜伏在相应日志路径

**修复**：统一替换为 structlog `from app.core.logging import logger`，覆盖 16 个模块：

| 模块 | 修改 |
|------|------|
| `agents/nodes/faq.py` | stdlib → structlog |
| `agents/nodes/auth.py` | stdlib → structlog |
| `agents/nodes/tools.py` | stdlib → structlog |
| `agents/nodes/validate.py` | stdlib → structlog |
| `agents/nodes/rewrite.py` | stdlib → structlog |
| `agents/cache.py` | stdlib → structlog |
| `agents/llm.py` | stdlib → structlog |
| `agents/graph.py` | stdlib → structlog |
| `services/audit_service.py` | stdlib → structlog |
| `services/document_service.py` | stdlib → structlog |
| `services/faq_service.py` | stdlib → structlog |
| `services/user_service.py` | stdlib → structlog |
| `core/minio_client.py` | stdlib → structlog |
| `api/agent/__init__.py` | `_logger` alias → structlog |
| `api/admin/auth.py` | `_auth_logger` alias → structlog |
| `api/admin/document.py` | stdlib → structlog |

- `agents/nodes/logging.py` 不动（使用有效的 stdlib `extra=` 模式，有 try/except 保护）
- 验证：`logging.getLogger` 在 `app/` 中只剩 `logging.py`（预期）

**顺带修复**：`rewrite.py:83` 导入的是 `acall_llm_with_retry` 但调用 `call_llm_with_retry` → 修正为 `acall_llm_with_retry`

### 额外修复 — FAQ 向量计数竞态

`load_faq_vectors_from_db()` 在设置全局变量后读取 `len(FAQ_VECTORS)` 作为返回计数，但并发 `_auto_refresh_faq_vectors` 可能直接覆盖该全局变量，导致计数变为 0（尤其是在测试中使用真实的 MySQL 连接时）。

**修复**：`_set_faq_vectors()` 现在在锁内返回 `int` 计数；`load_faq_vectors_from_db()` 直接返回此值，而非之后读取全局变量。
