# 一键发布模块改编计划

> 目标：将现有"后端直接调 CLI"的发布方式，改编为桥接器架构  
> 参考文档：`发布桥接器与多Chrome身份安装操作交接.md`  
> 日期：2026-07-29  
> 状态：待执行

---

## 架构对比

```
当前：
  后端 → asyncio.subprocess(wechatsync CLI) → 直接发布
  账号存的是：平台密码/Cookie/AppID

目标：
  后端 → HTTP POST 桥接器(3010) → 桥接器按账号组路由 CLI
       → CLI 连接 Chrome 扩展(WebSocket) → 浏览器已登录身份 → 平台草稿箱
  账号存的是：Chrome 扩展 Token + 账号组
```

### 1.3 `src/server.mjs` 核心逻辑

- HTTP 3010 端口
- `GET /health` — 健康检查，返回 `{ok: true, service: "...", group_ports: {...}}`
- `POST /api/publish` — 接收 `{title, content, platform, group, token}`
  1. 验证 group 合法（2113/2114/2119/3760）
  2. 写入临时 .md 文件
  3. 按账号组入队（每组串行执行，不同组可并行）
  4. 队列处理器：`spawn wechatsync sync {file} --platforms {platform} --port {cli_port} --token {token}`
  5. 等待 CLI 退出 → 返回 `{success, error}`

### 1.4 `start.cmd`

```cmd
@echo off
cd /d "%~dp0"
node src/server.mjs
pause
```

### 1.5 验证方式

```powershell
Set-Location "publisher-bridge"
npm.cmd install
npm.cmd start

# 健康检查（另开终端）
Invoke-RestMethod 'http://127.0.0.1:3010/health'
# 期望: { ok: true, service: "enterprise-kb-publisher-bridge", group_ports: {...} }
```

## 阶段 3：后端发布器改编

### 3.1 `backend/app/articles/publisher.py`

新增函数 `publish_via_bridge()`：

```python
async def publish_via_bridge(
    title: str, content_md: str, platform: str,
    account_group: str, token: str,
) -> dict:
    """通过本机桥接器发布（替代直接调 CLI）"""
    try:
        async with httpx.AsyncClient(timeout=120.0) as client:
            resp = await client.post(
                f"{settings.publisher_bridge_url}/api/publish",
                json={
                    "title": title,
                    "content": content_md,
                    "platform": platform,
                    "group": account_group,
                    "token": token,
                },
            )
            if resp.status_code == 200:
                return resp.json()
            return {"success": False, "url": None, "error": f"桥接器返回 {resp.status_code}"}
    except httpx.ConnectError:
        return {"success": False, "url": None, "error": "桥接器未启动(3010不可达)"}
```

保留 `publish_via_wechatsync()` 作为降级方案。

### 4.1 `backend/app/articles/service.py` — `publish_articles()`

获取凭证逻辑改为优先取 `account_group` + `ws_token`：

```python
account_group = ""
ws_token = ""
account_creds = {}

if account_id:
    account = await self.get_account(account_id)
    if not account:
        raise ValueError(f"账号 {account_id} 不存在")
    account_group = account.account_group or ""
    if account.ws_token:
        ws_token = decrypt_credentials(account.ws_token)
    if account.credentials:
        account_creds = json.loads(decrypt_credentials(account.credentials))
```

发布路由改为优先走桥接器：

```python
elif method == "wechatsync":
    if account_group and ws_token:
        result = await publish_via_bridge(
            article.title, article.content, pid,
            account_group=account_group, token=ws_token,
        )
    else:
        # 降级：无账号组/Token 时回退到直接 CLI 调用
        result = await publish_via_wechatsync(
            article.title, article.content, pid,
            credentials=account_creds or None,
        )
```

## 安全要求（来自文档）

- 平台密码只在平台官网填写，不进系统
- 每个浏览器身份使用独立 Token
- Token 不在日志、源码、截图中出现
- Token 后端加密存储（Fernet），从前端接口不返回明文
- 默认发布到草稿箱，不直接公开发布
- 批量发送前先验证单篇、单账号
