## 🔧 基础设施修复

### 1. WAF 默认方法白名单导致 PUT/DELETE 被 403 拦截

| 问题 | 原因 | 修复 |
|------|------|------|
| 分类编辑(PUT)、删除(DELETE)操作返回 403 | OWASP CRS 规则 911100 默认只允许 GET HEAD POST OPTIONS | `docker-compose.yml` waf 加 `ALLOWED_METHODS=GET HEAD POST PUT PATCH DELETE OPTIONS` |

### 2. 文件上传仅 12.5MB（不是宣称的 50MB）

| 问题 | 原因 | 修复 |
|------|------|------|
| >12.5MB 文件上传返回 403 | WAF ModSecurity 默认 `SecRequestBodyLimit=13107200` | 加 `MODSEC_REQ_BODY_LIMIT=52428800`（50MB） |
| 粘贴文本 >128KB 被拦 | 默认 `SecRequestBodyNoFilesLimit=131072` | 加 `MODSEC_REQ_BODY_NOFILES_LIMIT=5242880`（5MB，匹配后端 schema） |

### 3. Vite 开发代理指向旧服务器

`frontend/vite.config.ts` — `/api` 代理目标为 `http://124.221.218.182`（已被废弃的远程服务器），改为 `http://backend:8000`。后续进一步删除整个 proxy 配置（用户只用 `http://localhost` 经 nginx 访问，不直连 5173）。

### 4. 5173 直连端口关闭

`docker-compose.yml` frontend 服务 `ports: 5173:5173` → `expose: 5173`（仅容器内部网络可达）。

### 5. 每次启动报 WatchfilesRustInternalError

| 问题 | 原因 | 修复 |
|------|------|------|
| 后端每次启动内存报错 | `uvicorn --reload` 监视整个 `/app`（含 `models_cache/`、`.mypy_cache/` 等几十万文件） | backend 命令加 `--reload-dir /app/app` 仅监视代码目录 |

### 6. 冷启动依赖缺失

backend `depends_on` 缺少 elasticsearch 和 milvus → 冷启动时后端先于检索栈启动，FAQ 向量初始化跳过（`startup_cache_skip`）。已补 `elasticsearch: service_healthy` 和 `milvus: service_healthy`。

### 7. 一键启动脚本

新增 `start.ps1` — `docker compose up -d` → 等待容器 healthy → 等待 API 200 → 等待前端 200 → 输出"启动完成"。失败时打印未就绪容器名和日志。实测冷启动 21 秒完成。

## 🔧 前端功能修复

### 1. 审核中心不可用

`ReviewCenter.vue:109` — `fetchDocuments({ page_size: 200 })` 超过后端上限 100 → 422 错误 → `res.items` 为 undefined → 整页崩溃。

- `page_size: 200` → `100`
- `loadDocs` / `loadFaqs` 加 try/catch/finally
- `api/document.ts` / `api/faq.ts` 加 `if (!resp.ok) throw ...` 守卫

### 2. 新建文档表单统一 + 部门选择器（1a+2x）

**问题**：新建文档只有元数据表单 + 粘贴文本，缺少文件上传整合；内部范围无法指定部门。

**改动**：
- 统一新建表单：标题、分类、范围、部门（范围=内部时显示）、高级选项、可选文件
  - 选了文件 → 走 upload 接口一步完成（修复 `category_id || 1` 隐患）
  - 没选文件 → 创建空草稿
- 部门选择器：`el-select` `filterable` `allow-create` `clearable`（汇总自现有用户+文档的部门 + 手动输入）
- 文档列表新增"部门"列
- 非超管部门锁定为本人部门（前端禁用 + 后端强校验）

## 🔧 后端新增

### GET /api/admin/documents/departments

汇总 `sys_user` + `knowledge_doc` 中所有非空 department，去重排序返回 `string[]`。

### _guard_department 越权校验

非 superadmin 不能把文档挂到别的部门：
- `create_doc` → 传了不同 department → 403
- `upload_file` → 传了不同 department → 403
- 验证：dept_admin 市场部建本部门文档 → 201 ✅，建技术部文档 → 403 ✅

### upload_file 加 department Form 参数

`department or cu.department`，支持前端传部门。
