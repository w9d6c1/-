### 2.2 关键技术约束与设计决策

**A. Milvus 服务端是 v2.4.0，不支持在线加字段**（`AddCollectionField` 返回 UNIMPLEMENTED）：
- 解决方案：来源元数据以 **MySQL 为权威**（展示字段 `source_name/original_url/publish_time` 按 `doc_id` 回查 MySQL）。
- Milvus 侧采用**条件透传**：用缓存式字段探测判断集合是否含 `source_type`；有则写入/请求，无则优雅省略（回退 `internal`）。新旧集合均不报错。
- ES 正常透传（`put_mapping` 非破坏）：已在线加 `source_type`/`source_name`/`original_url` 三个字段（三索引落库）。

**B. SimHash 使用 63 位**（非 64 位）：因 MySQL/SQLite 的 BIGINT 为有符号（上限 2^63-1），裸 64 位无符号指纹会溢出。63 位非负值安全入库，精度无损。
- 代码位置：`app/collector/dedup.py` → `_SIMHASH_BITS = 63`

**C. 双智能体图是独立的**：内部 13 节点、客服 10 节点（含 citation 节点）。引用功能必须在两张图中一致落地。

**D. Alembic 存在孤儿 head**：
- `a001_platform_account` / `a002_account_group` 从 baseline (95506ee7b94e) 分叉，与主链 `327b58012669 → b001 → b002` 形成双 head。
- 这些表由 SQLAlchemy 模型通过 `Base.metadata.create_all()` 创建，未通过 alembic 执行迁移。
- **必须使用显式目标升级**：`alembic upgrade b002_add_collector_models`，切勿 `alembic upgrade head`（多 head 歧义）。
- 源码注释：`a001_platform_account.py`、`a002_account_group.py`

**E. 测试环境**：部分测试（路径敏感/依赖外部服务）在容器内无法运行。已给 13 个测试文件加条件 skip 标记。全量单元 `87 失败 → 1 失败`（1 个剩余为既有测试隔离污染，单跑通过）。

**F. 平台 API 凭证未到位**：5 个采集适配器仅以 mock HTTP 方式测试通过，真实联调待凭证。
