## 二、导出阻塞修复（事件循环卡死）

### 2.1 现象
批次 ZIP 导出期间**所有 API 挂起**（health 超时），导出本身 120s+ 无响应。

### 2.2 根因（两个叠加）
1. **同步阻塞**：zip 打包 + MinIO 下载直接在 async 端点内执行，阻塞 uvicorn 事件循环
2. **致命 Bug**：`api/articles.py` 批量导出的 `Content-Disposition` 头直接拼中文 topic 未做 URL 编码 → `StreamingResponse` 构造时 `UnicodeEncodeError`（HTTP 头 latin-1 限制），叠加 `BaseHTTPMiddleware` 异常处理缺陷卡死整个循环

### 2.3 修复
- `app/articles/service.py`：渲染/打包提取为同步函数 `_render_article` / `_build_batch_zip`，经 `asyncio.to_thread` 入线程池
- `app/api/articles.py`：文件名 `quote()` 编码（与单篇导出一致）

### 2.4 结果
导出 120s+ 卡死 → **0.11s**；导出期间 health 3ms 正常。

## 三、发布链路诊断与重构（本日核心）

### 3.1 诊断：历史上从未真正发布成功
- `publishing_record` 全部记录 failed，知乎草稿箱无文章
- **假成功链条**：
  ```
  Chrome 扩展未连接 → CLI 等 30s 超时打印安装指南 → 交互提问 (y/N) 因 stdin 关闭永久挂起
  → 桥接器 spawn 超时发 SIGTERM → CLI 的 SIGTERM 钩子恒 process.exit(0)（CLI 自身缺陷）
  → 桥接器见退出码 0 误报"发布成功"
  ```
- 证据：`@wechatsync/cli@1.1.0` 源码 `sync` 命令 `finally { process.exit(0) }`，退出码不可信

### 3.2 阶段一：失败判定修复（publisher-bridge/src/server.mjs）
- 不再信任退出码：解析 CLI 输出 `同步完成: X 成功, Y 失败` 判定真实结果
- 识别"连接超时/安装引导"文本 → 明确报错「Chrome 扩展未连接…」
- stdin 写入 `n` 防交互挂起；日志输出 CLI 完整 stdout

### 3.3 阶段二：发布异步队列化（方案 B）
- `app/articles/service.py publish_articles`：只建 pending 记录**秒回**（37ms），不再原地阻塞
- 去重保护：同 `(article_id, platform)` 已有 pending 时跳过
- `app/articles/schedule.py`：30s 调度器同时捞取 `scheduled_at IS NULL`（即时队列）与到期定时任务
- 新增 `GET /api/admin/articles/batches/{id}/publishing-status` 供前端轮询
- 前端 `PublishManager.tsx`：5s 轮询 + 文章行状态徽标（排队中/已发布/失败）+ 头部"发布进行中"指示
- 超时链对齐：CLI spawn 300s / 后端 httpx 330s

### 3.4 阶段三：桥接器 Docker 化
- 新增 `publisher-bridge/Dockerfile`（node:20-alpine + npm ci）与 `.dockerignore`
- `docker-compose.yml` 新增 `publisher-bridge` 服务：3010（后端调用）+ 9531–9538（扩展 WS）
- 后端默认 `publisher_bridge_url=http://host.docker.internal:3010` 无需改动

### 3.5 阶段四：账号组 3760 → 9023
- 改名位置：`server.mjs` GROUP_PORTS、`start.cmd`、`Accounts.tsx`、`models.py`/`schemas.py` 注释、交接文档
- WS/CLI 端口不变（9537/9538）；DB 无 3760 组账号，无需迁移

### 3.6 阶段五：常驻 WS 网关（去掉 CLI）
- **问题**：扩展不自动重连，只在用户操作扩展时尝试连接；CLI 临时监听窗口（哪怕 240s）总错过
- **方案**：桥接器启动即常驻监听 4 个 WS 端口，直连扩展发 `syncArticle`（协议 `{id, method, token, params}` → `{id, result}`），markdown→HTML 转换从 CLI 实现复刻；新增 `ws` 依赖
- `/health` 增加 `extension_connected` 实时状态

### 3.7 阶段六：心跳保活
- **问题**：Chrome MV3 service worker 空闲回收 → 扩展连上后几十秒断开
- **方案**：连接期间每 20s 发心跳消息保活（`KEEPALIVE_INTERVAL_MS`）
