## 今日完成

### 阶段一：React 管理后台全面接入后端 API

- **架构转变**：`app/` React 应用从纯 localStorage 单机应用改为对接 FastAPI 后端
- **删除废弃代码**：
  - `src/lib/db.ts` — localStorage 假数据库
  - `src/lib/rag.ts` — 浏览器端 RAG 检索
  - `src/lib/ai.ts` — 浏览器端 AI 调用
  - `src/lib/seo.ts` — 浏览器端 SEO 生成
  - `src/lib/parsers/` — 浏览器端文件解析（Word/PDF/CSV）
- **新建 API 层**（6 个文件）：
  - `src/api/client.ts` — Axios 实例 + JWT 拦截器 + 401 自动跳转
  - `src/api/auth.ts` — 登录/验证码/用户信息
  - `src/api/documents.ts` — 知识库文档 CRUD + 分块/重同步
  - `src/api/articles.ts` — 批次/文章/发布/导出/SSE/模板/模仿
  - `src/api/users.ts` — 用户管理 CRUD
  - `src/api/dashboard.ts` — 仪表盘统计
- **认证系统**：`src/stores/auth.tsx` — React Context AuthProvider + useAuth Hook
- **登录页**：`src/pages/Login.tsx` — 手机验证码登录（默认）+ 密码登录

### 阶段三：照片功能全链路

- **照片代理端点**：`GET /api/admin/articles/photos/{object_name:path}` — MinIO 代理
- **ArticleDetail 渲染**：`[IMAGE: 配图建议: xxx]` 标记替换为 `<img>` 标签
- **导出时嵌入**：
  - DOCX：`python-docx add_picture()` 内联嵌入
  - HTML：base64 `<img src="data:image/jpeg;base64,...">` 离线可用
  - MD：`![caption](photo_url)` 引用代理链接
  - ZIP：含 `photos/` 文件夹，相对路径引用
- **Vision API 失效兜底**：分析全失败时自动追加兜底指引，LLM 仍能产出 `[IMAGE]` 标记
- **Prompt 修复**：配图要求从 SEO 段第 6 条提升为独立 `## 配图要求（必须遵守）` 章节
- **修复文章截断**：`article_min_words: 500→1200`、`article_max_words: 800→3000`、`max_tokens: 1800→3200`、截断阈值放宽到 2 倍

### 阶段四：模仿创作模块

- **`app/articles/imitate.py`** — 新建 3 个函数：
  - `analyze_style(source_text)` — LLM 分析 5 维度（语气/开头/结构/论证/结尾）
  - `retrieve_knowledge(topic)` — 调用 hybrid_retrieve 检索知识库
  - `imitate_article(topic, style, knowledge)` — 基于风格模板 + 知识库生成新文章
- **API 端点**：
  - `POST /admin/articles/analyze-style` — 风格分析
  - `POST /admin/articles/imitate` — 模仿创作（自动创建批次 + 存储）
- **前端**：批量生成页加"模仿创作"Tab，3 步流程（粘贴参考 → 分析风格 → 模仿生成）

### 阶段五：写作模板系统

- **ORM 模型**：`WritingTemplate`（`writing_template` 表）
  - 字段：`id, user_id, name, type(structure/style), prompt_instruction, is_preset, sort_order`
- **模板服务**：`app/articles/template_service.py`

- **API 端点**：`GET/POST/PUT/DELETE /admin/articles/templates`

- **前端页面**：

  - `BatchGenerate.tsx` — 第 4 步"选择模板"（可选跳过，可组合结构+风格）

### 阶段六：照片库系统

- **需求**：照片一次入库带标签，创作时 AI 自动匹配，防重复，描述复用
- **数据模型**（`app/articles/models.py`）：
  - `Photo` 表 — `id, object_name, filename, tags(JSON), description, file_size, content_type, user_id`
  - `BatchPhoto` 表 — `id, batch_id, photo_id, article_id, used_at`（防重复窗口追踪）
- **照片业务层**（`app/articles/photo_service.py`）：
  - `upload_photo()` — MinIO 存储 → Vision API 分析 → 返回 AI 标签 + 描述
  - `match_photos()` — LLM 提取主题关键词 → 标签匹配 → 排除窗口期内已用照片
  - `suggest_tags()` — 重新为已有照片生成 AI 标签建议
  - 照片 CRUD（list/get/update/delete）
  - 批次-照片关联（select_photos_for_batch / mark_batch_photos_used）
- **API 端点**（`app/api/articles.py`）：
  - `POST /photos/upload` — 上传到照片库
  - `GET /photos` — 列表（分页、标签筛选）
  - `GET /photos/{id}` / `PUT` / `DELETE` — CRUD
  - `POST /photos/{id}/suggest-tags` — 重新 AI 打标签
  - `POST /photos/match` — 智能匹配
  - `POST /batches/{batch_id}/select-photos` — 关联照片到批次
- **生成流程改造**（`app/articles/service.py`）：
  - `run_generation()` 支持照片库模式：直接读 `Photo.description`，跳过 Vision API
  - 生成完成后 `mark_batch_photos_used()` 更新 `used_at`
  - `start_generation` API 增加 `use_photo_library` 参数
- **前端照片库页**（`app/src/pages/PhotoLibrary.tsx`）：
  - 网格缩略图视图 + 大图弹窗预览
  - 上传自动 AI 打标签 + 人工确认/编辑
  - 标签搜索过滤 + 分页
- **前端 API 层**（`app/src/api/photos.ts`）：
  - 7 个 API 函数 + `fetchPhotoBlob()` 认证图片加载
- **前端改造**：
  - `App.tsx` — 新增 `/photos` 路由
  - `Sidebar.tsx` — 新增「照片库」菜单
  - `BatchGenerate.tsx` — Step 2 双模式（智能匹配 + 手动上传）**（待逐步加回，白屏问题待定位）**
- **配置**：`app/core/config.py` 新增 `photo_reuse_window_days: 30`、`photo_match_count: 5`
- **数据库**：MySQL 已创建 `photo`、`batch_photo` 表
