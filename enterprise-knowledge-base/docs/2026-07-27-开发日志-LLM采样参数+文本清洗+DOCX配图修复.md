# 2026-07-27 开发日志 — LLM 采样参数 + 文本清洗 + DOCX 配图修复

## 一、LLM 采样参数全局添加 `top_p`

### 背景
项目所有 LLM 调用仅配置了 `temperature`，缺少 `top_p` 参数控制采样空间。

### 改动
- **`config.py`**：新增 `llm_top_p: float = 0.9`（全局默认）、`article_top_p: float = 0.85`（文章生成默认）
- **`llm.py`**：`create_llm()` 增加 `top_p` 参数，通过 `model_kwargs` 传给 DeepSeek API；默认回退 `settings.llm_top_p`
- **所有调用点（16 处）**：补齐 `top_p` 显式值

### 取值
| 场景 | temperature | top_p |
|------|:-----------:|:-----:|
| AI 问答生成 | 0.2 | 0.85 |
| 客户智能体 | 0.2 | 0.85 |
| 文章生成（技术/对比/选购等） | 0.4 | 0.85 |
| 文章生成（案例/角度规划） | 0.5 | 0.9 |
| 模仿生成 | 0.6 | 0.9 |
| 查询改写 / 工具调用 | 0.0 | 1.0 |

## 二、LLM 输出后置清洗

### 背景
DeepSeek 模型输出偶发包含 `#` `*` `—` 等 Markdown 符号和 `...` 思考过程，影响用户阅读。

### 方案：两层防护

**第一层 — 输入端（RAG 上下文）**：检索文档喂给 LLM 前清洗

| 文件 | 位置 | 改动 |
|------|------|------|
| `context.py` | `_format_doc()` | `clean_response(doc.content)` 清洗每个文档片段 |
| `faq.py` | 入 context 前 | `clean_response(best_answer)` |
| `customer/faq.py` | 同上 | 同上 |
| `generator.py` | `generate_single_article()` | 每段 `retrieved_context` 清洗 |
| `generator.py` | `generate_batch()` | `knowledge_summary` 每段清洗 |

**第二层 — 输出端（LLM 结果）**：返回用户前清洗

| 文件 | 改动 |
|------|------|
| `llm.py` | 新增 `clean_response()` 函数（9 步清洗管道），`call_llm_with_retry`/`acall_llm_with_retry` 增加 `clean` 参数 |
| `generate.py` | 流式收集后 `clean_response(answer)` |
| `customer/generate.py` | 同上 |
| `generator.py` | 标题 + 正文 `clean=True` |
| `imitate.py` | 生成调用 `clean=True` |
| `dictionary.py` | `ainvoke` 后手动 `clean_response()` |

### `clean_response()` 清洗步骤
1. 删除 `...` 思考块（含未闭合）
2. 删除 `` / `` 残留标签
3. 删除开头机械开场白（"好的，让我分析一下..."）
4. 逐行清除行首 `#` 标题、`>` 引用、`-` `*` 列表标记
5. 删除代码块 `\`\`\`...\`\`\``
6. 删除独立分割线行 `---` / `***`
7. 删除连续长破折号 `————`
8. 压缩多余空行（3+ → 2）
9. 保留 `**加粗**` 和 `1./2.` 序号

### 存量文档清洗
- 创建 `scripts/batch_clean_text.py` 批处理脚本
- 支持 `--dry-run` 预览、`--skip-sync` 控制
- 干跑结果：22 个存量文档中 19 个无需清洗，3 个已自动空白规范化
- 流程：`clean plain_text` → `rechunk` → `sync ES+Milvus`

## 三、DOCX 下载配图修复

### Bug 1：三张照片只下载一张
**根因**：`publisher.py:386` — 行内标记处理 `break` 只处理第一个 marker，同段落内后续标记丢失。

**修复**：收集 block 中所有 marker 位置 → 排序 → 按序插入文字段 + 图片。

### Bug 2：去重导致 placements 数组缩水
**根因**：`generator.py:_extract_image_placements` 对 caption 做了 `seen` 去重，导致 3 个标记只留 1-2 个 placement。

**修复**：移除去重逻辑，每个标记独立生成 placement；照片分配改用 `len(placements)` 作为索引。

### Bug 3：照片下标注显示 `[图片: [IMAGE: ...]]` 而非纯文本
**根因**：`publisher.py:357` — `type(r.font.color.rgb)(0x88, 0x88, 0x88)` 首次访问 `rgb` 为 `None`，`type(None)` 不接受参数，抛出异常 → 走到 fallback `[图片: block]` 输出原始标记。

**修复**：改用 `RGBColor(0x88, 0x88, 0x88)` 替代脆弱的 `type()` 反射。

### Bug 4：配图下标注过长
**修复**：`_ARTICLE_PROMPT` 和 `_IMITATE_PROMPT` 中配图指令改为 "简短明确，控制在 15 字以内"。
