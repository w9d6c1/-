## 🧪 多轮记忆修复 — 尝试过程

### 尝试 1：aupdate_state 在 API 层回写

在 `_do_chat` / `_stream_events` / `customer_chat` / `_customer_stream_events` 4 处，`graph.ainvoke()` 返回后调用 `graph.aupdate_state(config, {"messages": [AIMessage]})`。

**结果：** ❌ 失败。R2 仍然不记得 R1。

**根因：** `aupdate_state` 用 `[AIMessage]` 替换了整个 messages 列表，覆盖了原有的 HumanMessage。

### 尝试 2：aupdate_state 读取 + 追加 + 写回

```python
saved_after = await graph.aget_state(config)
msgs = list(saved_after.values.get("messages", []))
msgs.append(AIMessage(content=answer))
await graph.aupdate_state(config, {"messages": msgs})
```

**结果：** ❌ 失败。原因不明——可能 LangGraph `LastValue` channel 对 `aupdate_state` 的处理与预期不同，或 graph 内部机制覆盖。

### 尝试 3：generate_node 内部追加 AIMessage

在 `generate_node` 的 `return result` 前：
```python
msgs = list(result.get("messages", []))
msgs.append(AIMessage(content=result["final_answer"]))
result["messages"] = msgs
```

让 `graph.ainvoke()` 自然保存。

**结果：** ❌ 失败。`checkpoint_writes` 中 messages 仍只有 1 条 HumanMessage（len=152~153），AIMessage 未落盘。

### 尝试 4：generate_node 传对话历史给 LLM

```python
history = state.get("messages", [])
messages = [SystemMessage(...)]
messages.extend(history)
messages.append(HumanMessage(content=f"参考文档：\n{context}\n\n请基于以上对话历史和参考文档回答用户最新问题。"))
```

### 尝试 5：删除 aupdate_state，仅靠 graph 机制

删除了 `agent/__init__.py` 中所有 `aupdate_state` 调用，避免与 graph 内部机制冲突。`generate_node` 中 AIMessage 追加保留。
