## ✅ 任务 1：SMS 验证码登录修复

### 故障现象

用户反馈无法收到短信验证码，收到后登录也失败。

### 根因分析（按排查顺序）

| # | 问题 | 根因 | 影响 |
|---|------|------|------|
| 1 | 容器读不到 SMS 配置 | `.env` 有值但 `backend` 容器未重建 | 四个 SMS 变量全空，`_sms_configured()` 返回 False |
| 2 | 公网调用 403 | nginx `ip-whitelist.inc` `deny all` 拦截了 `/api/admin/*` | 外部用户无法发验证码 |
| 3 | 阿里云 API 403 | RAM 子账号无 `AliyunDysmsFullAccess` 权限 | 短信 API 直接拒绝 |
| 4 | 验证码存不进 Redis | `.env` 缺 `REDIS_HOST=redis`，`config.py` 默认 `localhost` | `sms_code_store_failed`，登录验证时 Redis 无码 |
| 5 | 登录 500 | `.env` 缺 `MYSQL_HOST=mysql`，`config.py` 默认 `localhost` → 连不上 MySQL | 全部数据库操作失败 |
| 6 | `sys_user` 无 `phone` 列 | `01-schema.sql` 与 SQLAlchemy 模型不同步 | `phone_login` 报 Unknown column |
| 7 | 登录 500（二轮） | MySQL 容器重建后 `kb_user` 丢失、`knowledge_base` 库丢失 | 数据库完全空 |
| 8 | 登录 500（三轮） | `sys_user` 表重新导入后仍缺 `phone` 列（服务器 git 未 pull） | 同 #6 |

### 核心问题：`config.py` 默认值陷阱

`config.py` 中 5 个 `*_HOST` 默认值均为 `localhost`，但 Docker 内服务主机名不等于 `localhost`：

| 变量 | 默认值 | Docker 内实际值 |
|------|--------|----------------|
| `mysql_host` | `localhost` | `mysql` |
| `redis_host` | `localhost` | `redis` |
| `postgres_host` | `localhost` | `postgres` |
| `es_host` | `localhost` | `elasticsearch` |
| `milvus_host` | `localhost` | `milvus` |

虽然 `.env.example` 正确填写了 Docker 主机名，但生产 `.env` 是从旧版本延续的，缺少这些变量。

## ✅ 任务 2：服务器稳定性

### 故障现象

网页间歇性无法访问（502/连接拒绝）。

### 根因分析

| # | 问题 | 根因 |
|---|------|------|
| 1 | OOM Killer 随机杀容器 | 物理内存 3.6GB，容器上限合计 3.9GB，超物理内存 |
| 2 | nginx 崩溃无限重启 | 停 grafana 后 nginx 解析不到 `grafana` 主机名 → `host not found in upstream` |
| 3 | 服务器重启后服务丢失 | 无 systemd 自启服务 |

### 修复

| 操作 | 详情 |
|------|------|
| 添加 2GB Swap | `/swapfile`，`/etc/fstab` 持久化 |
| 停掉 WAF 导致 502 | nginx upstream 是 `waf:8080`，停 WAF 需同步改 nginx 或保留 WAF |
| 创建 systemd 服务 | `/etc/systemd/system/kb.service`，`systemctl enable kb` |

### 警告：nginx ↔ grafana 耦合

`docker/nginx/conf.d/default.conf:96-100` 的 `/grafana/` location 引用了 `grafana:3000`。停 grafana 会导致 nginx 启动失败。要彻底解耦需从 nginx 配置删除该 location。
